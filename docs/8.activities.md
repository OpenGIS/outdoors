# Activities

> The `WAYMARKED_ROUTES` and `WAYMARKED_CYCLING_ROUTES` toggles control the waymarked hiking- and cycling-route overlays; other activity layers remain reference implementations.

Waymarked hiking and cycling routes are the style's activity-specific overlays, drawn from hosted tiles as width-tiered hierarchies — one hue per family across the four marked networks, plus a shared neutral unmarked treatment — with badges on the marked networks only; separate `WAYMARKED_ROUTES` and `WAYMARKED_CYCLING_ROUTES` toggles control them. Other activity-based layers stay out of scope. The MTB scale below remains a reference implementation, while both hosted OSM line overlays are generated by Planetiler Java profiles that live in [`docs/examples/`](examples/): [`examples/FootpathOverlay.java`](examples/FootpathOverlay.java) for the low-zoom paths overlay and [`examples/RouteOverlay.java`](examples/RouteOverlay.java) for the routes overlay. See [Tile Server](7.server.md).

## Hiking Routes

[![Waymarked routes at Andermatt, showing oxblood linework and a major route badge](../screenshots/andermatt-routes.jpg)](https://www.ogis.org/outdoors/#10/46.6344/8.5931)

OSM hiking route relations (`type=route|superroute`, `route=hiking|foot|walking`) become line vector tiles, so long-distance routes read as a hierarchy on the map. The same archive also carries cycling routes (see [Cycling Routes](#cycling-routes)); hiking member ways carry `route_type=hiking`. The hosted service is listed at [`tile.ogis.app/sources`](https://tile.ogis.app/sources) as a PMTiles-backed vector service: worldwide hiking and cycling routes rebuilt weekly from OpenStreetMap, served at `https://tile.ogis.app/routes/{z}/{x}/{y}.pbf` with source-layer `outdoor_routes` across z8–14.

The tile schema follows [`examples/RouteOverlay.java`](examples/RouteOverlay.java), based on Planetiler's [BikeRouteOverlay example](https://github.com/onthegomap/planetiler/blob/main/planetiler-examples/src/main/java/com/onthegomap/planetiler/examples/BikeRouteOverlay.java): one line feature per route-member way, carrying `name`, `ref`, `network`, `route_type`, `osmc_symbol`, `operator`, `distance`, `ascent`, `descent`, `cai_scale` and `roundtrip`. The style consumes the source at z8–14.

### Network tiers

[`applyWaymarkedRoutes()`](../scripts/build.mjs) adds the `outdoor-routes` source and draws the tiers lowest priority first, so a segment shared by several routes takes the highest network's width. The table lists the resulting hierarchy widest first:

| Network | Tier          | From | Linework                                     |
| ------- | ------------- | ---- | -------------------------------------------- |
| `iwn`   | International | z8   | Solid oxblood, ivory casing                  |
| `nwn`   | National      | z8   | Solid oxblood, ivory casing                  |
| `rwn`   | Regional      | z9   | Solid oxblood, ivory casing                  |
| `lwn`   | Local         | z12  | Solid oxblood, ivory casing                  |
| —       | Unmarked      | z12  | Dashed neutral grey, softer casing, no badge |

All four marked networks share the oxblood fill (`#8e3b3b`); hierarchy is carried by width alone, widest at `iwn` and narrowing through `nwn`, `rwn` and `lwn`, with the unmarked tier narrowest. Each tier draws a 1.35× ivory (`#fff8f0`) casing beneath its fill. Marked lines are solid: `iwn`/`nwn` fill at alpha `0.57` under a `0.4` casing, and `rwn`/`lwn` at `0.65` under a `0.3` casing so the thinner lines stay saturated. The unmarked tier covers absent, empty and unknown `network` values, so no way slips through without a line: it is a neutral warm-grey (`#6f6862`) line-only tier (no badge) from z12, dashed `[4, 2]`, with fill alpha `0.5` and a softer `0.25` casing. Because the archive also carries cycling, the hiking unmarked filter requires `route_type` other than `bicycle`; the four marked hiking tiers match the hiking vocabulary, which is disjoint from cycling's. Widths interpolate with zoom across every tier. Because `applyWaymarkedRoutes()` emits every colour as a native `rgba()` string through `routeColour()`, the alphas compose without a `line-opacity` paint property.

### Design rationale

The underlying path network is burnt-orange (`#c05a2a`) and reads as capillaries; the waymarked routes are the larger oxblood vessels above it. Hierarchy comes from a quiet width ladder with casings and no glow or gradient, so the routes read as one system without adding a second competing palette.

### Badges

Badge symbol layers repeat a single shield along the marked lines only: major badges from z10 for the international and national networks, local badges from z12 for regional and local routes. Unmarked ways carry no badge because they have no waymarked network. Badge text is `ref`, falling back to `name`; a feature with neither emits no badge. The hiking shield is one solid oxblood `route_marked` pill with cream text (`#fff8f0`), fitted around the text with `icon-text-fit: both`, set in `Noto Sans Bold` and spaced by `ROUTE_BADGE_SPACING` (400). Both the shield and its text paint fully opaque: the badge layers set no `icon-opacity`, so the pill shows the exact oxblood token rather than blending with the ground beneath. Both badge layers are line-placed; major badges are added first, so they win placement collisions against local shields.

### Render placement

The whole block — both families' tier lines, casings and badges — is inserted after the `Disputed border` linework and before the first label layer (`River labels`), so routes sit above transportation and boundaries but below every label. Within the block the cycling family is assembled first, so it draws beneath hiking; within the hiking family the line tiers run lowest priority first (unmarked, `lwn`, `rwn`, `nwn`, `iwn`), followed by the major badge layer and then the local badge layer. The style wiring is in [Style Structure](2.style.md#outdoor-overlays).

Thanks to [Waymarked Trails: Hiking](https://hiking.waymarkedtrails.org/#help-about) and [Waymarked Trails: Cycling](https://cycling.waymarkedtrails.org/#help-about), which have lots of useful information and also offer mtb, riding (equestrian), skating and slopes (skiing) in addition to hiking and cycling.

## Cycling Routes

OSM cycling route relations (`type=route|superroute`, `route=bicycle`) share the hiking archive: the hosted service emits them as the same `outdoor_routes` line tiles, tagged `route_type=bicycle`. The tile schema is the same [`examples/RouteOverlay.java`](examples/RouteOverlay.java) profile described above, and the `WAYMARKED_CYCLING_ROUTES` toggle controls the family.

### Network tiers

[`applyWaymarkedRoutes()`](../scripts/build.mjs) builds the family from `CYCLING_ROUTE_TIERS`, drawing the tiers lowest priority first so a segment shared by several routes takes the highest network's width. The table lists the resulting hierarchy widest first:

| Network | Tier          | From | Linework                                     |
| ------- | ------------- | ---- | -------------------------------------------- |
| `icn`   | International | z8   | Solid indigo, ivory casing                   |
| `ncn`   | National      | z8   | Solid indigo, ivory casing                   |
| `rcn`   | Regional      | z9   | Solid indigo, ivory casing                   |
| `lcn`   | Local         | z12  | Solid indigo, ivory casing                   |
| —       | Unmarked      | z12  | Dashed neutral grey, softer casing, no badge |

All four marked networks share the indigo fill (`#46589f`); hierarchy is carried by width alone, widest at `icn` and narrowing through `ncn`, `rcn` and `lcn`, with the unmarked tier narrowest. Each tier draws a 1.35× ivory (`#fff8f0`) casing beneath its fill. Marked lines are solid: `icn`/`ncn` fill at alpha `0.57` under a `0.4` casing, and `rcn`/`lcn` at `0.65` under a `0.3` casing so the thinner lines stay saturated. The unmarked tier covers absent, empty and unknown `network` values for cycling ways: neutral warm-grey (`#6f6862`) from z12, dashed `[4, 2]` with a butt cap, fill alpha `0.5` and a softer `0.25` casing. Its filter requires `route_type=bicycle` and a `network` outside the four cycling values, so it never takes hiking ways; the four marked cycling tiers need no `route_type` guard because the cycling vocabulary is disjoint from hiking's. Because `applyWaymarkedRoutes()` emits every colour as a native `rgba()` string through `routeColour()`, the alphas compose without a `line-opacity` paint property.

### Width ladder

Both families read widths from the shared `ROUTE_WIDTHS` table, so rank rather than activity sets the width. The stops, in px:

| Rank          | Zoom stops                                     |
| ------------- | ---------------------------------------------- |
| Unmarked      | z12 1.6 → z14 2.0 → z16 2.6                    |
| Local         | z12 1.8 → z14 2.6 → z16 3.6                    |
| Regional      | z9 1.6 → z11 2.4 → z13 3.4 → z15 4.8 → z16 5.2 |
| National      | z8 1.6 → z10 2.5 → z12 3.5 → z14 5 → z16 6.6   |
| International | z8 2 → z10 3.2 → z12 4.4 → z14 6.6 → z16 8.8   |

The casing is always 1.35× the fill width at the same stops, so the ivory halo scales with the tier rather than adding a flat shoulder that would flatten the hierarchy.

### Design rationale

Waymarked Trails distinguishes cycling networks by hue; this style keeps the whole family on one indigo (`#46589f`) because the width ladder already carries the hierarchy and a second multi-hue palette would compete with the path network's burnt-orange capillaries beneath it. The indigo is deliberately darker and more violet than the pale water blue, and stays clear of both the path orange and the basemap's azure chips. Hierarchy comes from a quiet width ladder with casings and no glow or gradient, so hiking and cycling read as two line families of one system.

### Badges

Badge symbol layers repeat the cycling shield along the marked lines only: major badges from z10 for `icn` and `ncn`, local badges from z12 for `rcn` and `lcn`. Unmarked ways carry no badge. Badge text is `ref`, falling back to `name`; a feature with neither emits no badge. The sprite icon is one solid indigo `route_marked_cycling` pill with cream text (`#fff8f0`) — the same 14×14 rounded-rectangle geometry as the hiking `route_marked` shield — fitted around the text with `icon-text-fit: both`, set in `Noto Sans Bold` and spaced by `ROUTE_BADGE_SPACING` (400). Both the shield and its text paint fully opaque: the badge layers set no `icon-opacity`, so the pill shows the exact indigo token rather than blending with the ground beneath. Both badge layers are line-placed; major badges are added first, so they win placement collisions against local shields.

### Render placement

The cycling family is assembled before hiking, so where a way carries both activities the hiking line and badges paint over the cycling ones. There is no lateral offset and no dashed-overlay treatment on shared ways: the lower cycling line simply sits beneath the hiking line. Within the family the tiers run lowest priority first (unmarked, `lcn`, `rcn`, `ncn`, `icn`), followed by the major badge layer and then the local badge layer. The shared block's position in the render stack is described under [Hiking Routes](#hiking-routes).

### Deferred node networks

Cycling relations tagged `state=proposed` are excluded because they are not yet signposted on the ground. Cycling node networks (`network:type=node_network`) are deferred: their dense short-hop webs are out of scope for this overlay. A relation carrying both hiking and cycling is emitted once as hiking — the profile's precedence, matching the overlay's draw order.

## MTB Scale

[![MTB Scale](examples/mtb-scale.png)](https://www.ogis.org/outdoors/#14.2/43.1083/-72.90997)

The MTB scale overlay colours ways by mountain bike difficulty, using the [`mtb_scale`](https://wiki.openstreetmap.org/wiki/Key:mtb:scale) tag from the OpenMapTiles transportation source-layer.

This reference implementation, based on [this comment](https://github.com/hyperknot/openfreemap/issues/31#issuecomment-4649028862), works well; however, different rating systems exist, like [mtb:scale:imba](https://wiki.openstreetmap.org/wiki/Key:mtb:scale:imba), which — like most other activity-based tags — are not included in the tile schema.

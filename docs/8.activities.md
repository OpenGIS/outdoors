# Activities

> The `WAYMARKED_ROUTES` toggle controls the waymarked hiking-routes overlay; other activity layers remain reference implementations.

Waymarked hiking routes are the style's activity-specific overlay, drawn from hosted tiles as a width-tiered hierarchy — one oxblood colour across the four marked networks, plus a neutral unmarked tier — with badges on the marked networks only; the `WAYMARKED_ROUTES` toggle controls it. Other activity-based layers stay out of scope. The MTB scale below remains a reference implementation, while both hosted OSM line overlays are generated by Planetiler Java profiles that live in [`docs/examples/`](examples/): [`examples/FootpathOverlay.java`](examples/FootpathOverlay.java) for the low-zoom paths overlay and [`examples/HikingRouteOverlay.java`](examples/HikingRouteOverlay.java) for the routes overlay. See [Tile Server](7.server.md).

## Hiking Routes

[![Waymarked routes at Andermatt, showing oxblood linework and a major route badge](../screenshots/andermatt-routes.jpg)](https://www.ogis.org/outdoors/#10/46.6344/8.5931)

OSM hiking route relations (`type=route|superroute`, `route=hiking|foot|walking`) become line vector tiles, so long-distance routes read as a hierarchy on the map. The hosted service is listed at [`tile.ogis.app/sources`](https://tile.ogis.app/sources) as a PMTiles-backed vector service: worldwide hiking routes rebuilt weekly from OpenStreetMap, served at `https://tile.ogis.app/routes/{z}/{x}/{y}.pbf` with source-layer `outdoor_routes` across z0–14.

The tile schema follows [`examples/HikingRouteOverlay.java`](examples/HikingRouteOverlay.java), based on Planetiler's [BikeRouteOverlay example](https://github.com/onthegomap/planetiler/blob/main/planetiler-examples/src/main/java/com/onthegomap/planetiler/examples/BikeRouteOverlay.java): one line feature per route-member way, carrying `name`, `ref`, `network`, `osmc_symbol`, `operator`, `distance`, `ascent`, `descent`, `cai_scale` and `roundtrip`. The style consumes the source at z8–14.

### Network tiers

[`applyWaymarkedRoutes()`](../scripts/build.mjs) adds the `outdoor-routes` source and draws the tiers lowest priority first, so a segment shared by several routes takes the highest network's width. The table lists the resulting hierarchy widest first:

| Network | Tier          | From | Linework                                     |
| ------- | ------------- | ---- | -------------------------------------------- |
| `iwn`   | International | z8   | Solid oxblood, ivory casing                  |
| `nwn`   | National      | z8   | Solid oxblood, ivory casing                  |
| `rwn`   | Regional      | z9   | Solid oxblood, ivory casing                  |
| `lwn`   | Local         | z12  | Solid oxblood, ivory casing                  |
| —       | Unmarked      | z12  | Dashed neutral grey, softer casing, no badge |

All four marked networks share the oxblood fill (`#8e3b3b`); hierarchy is carried by width alone, widest at `iwn` and narrowing through `nwn`, `rwn` and `lwn`, with the unmarked tier narrowest. Each tier draws a 1.35× ivory (`#fff8f0`) casing beneath its fill. Marked lines are solid: `iwn`/`nwn` fill at alpha `0.57` under a `0.4` casing, and `rwn`/`lwn` at `0.65` under a `0.3` casing so the thinner lines stay saturated. The unmarked tier covers absent, empty and unknown `network` values, so no way slips through without a line: it is a neutral warm-grey (`#6f6862`) line-only tier (no badge) from z12, dashed `[4, 2]`, with fill alpha `0.5` and a softer `0.25` casing. Widths interpolate with zoom across every tier. Because `applyWaymarkedRoutes()` emits every colour as a native `rgba()` string through `routeColour()`, the alphas compose without a `line-opacity` paint property.

### Design rationale

The underlying path network is burnt-orange (`#c05a2a`) and reads as capillaries; the waymarked routes are the larger oxblood vessels above it. Hierarchy comes from a quiet width ladder with casings and no glow or gradient, so the routes read as one system without adding a second competing palette.

### Badges

Badge symbol layers repeat a single shield along the marked lines only: major badges from z10 for the international and national networks, local badges from z12 for regional and local routes. Unmarked ways carry no badge because they have no waymarked network. Badge text is `ref`, falling back to `name`; a feature with neither emits no badge. The sprite icon is one solid oxblood `route_marked` pill with cream text (`#fff8f0`), fitted around the text with `icon-text-fit: both`, set in `Noto Sans Bold` and spaced by `ROUTE_BADGE_SPACING` (400). Both the shield and its text paint fully opaque: the badge layers set no `icon-opacity`, so the pill shows the exact oxblood token rather than blending with the ground beneath. Both badge layers are line-placed; major badges are added first, so they win placement collisions against local shields.

### Render placement

The whole block — tier lines, casings and badges — is inserted after the `Disputed border` linework and before the first label layer (`River labels`), so routes sit above transportation and boundaries but below every label. Within the block the line tiers run lowest priority first (unmarked, `lwn`, `rwn`, `nwn`, `iwn`), followed by the major badge layer and then the local badge layer. The style wiring is in [Style Structure](2.style.md#outdoor-overlays).

Thanks to [Waymarked Trails: Hiking](https://hiking.waymarkedtrails.org/#help-about), which has lots of useful information and also offers cycling, mtb, riding (equestrian), skating and slopes (skiing) in addition to hiking.

## MTB Scale

[![MTB Scale](examples/mtb-scale.png)](https://www.ogis.org/outdoors/#14.2/43.1083/-72.90997)

The MTB scale overlay colours ways by mountain bike difficulty, using the [`mtb_scale`](https://wiki.openstreetmap.org/wiki/Key:mtb:scale) tag from the OpenMapTiles transportation source-layer.

This reference implementation, based on [this comment](https://github.com/hyperknot/openfreemap/issues/31#issuecomment-4649028862), works well; however, different rating systems exist, like [mtb:scale:imba](https://wiki.openstreetmap.org/wiki/Key:mtb:scale:imba), which — like most other activity-based tags — are not included in the tile schema.

# Terminology

This glossary defines the vocabulary used across the project.

## Core Concepts

**Activity** — A waymarked-route mode (`hiking` or `cycling`) registered in the style's `ROUTE_ACTIVITIES` list. A tile feature's `activity` selects its tier family; its `activities` value carries the relation's full set in priority order, which the style uses to decide ownership of shared ways. See [Activities](7.activities.md).

**Anchor** — The layer id relative to which a build modification inserts its layers, preserving the surrounding stack order. Examples: `contour-lines` is inserted after `River bridge outline`; `outdoor-poi` after `Zoo`; the low-zoom path layers before `Footway path`; the waymarked-route block after `Disputed border`; `contour-labels` below the basemap's peak label layers.

**Basemap** — The OpenGIS Basemap: the vendored OpenMapTiles OSM style v3.16 pointed at OpenFreeMap planet tiles, published at <https://www.ogis.org/basemap/> (upstream repo: [opengis/basemap](https://github.com/opengis/basemap)). The build fetches its `style.json` and applies the outdoor modifications on top. See [Build Script](1.build.md).

**Benchmark harness** — The performance benchmark for the compare app ([`scripts/bench/bench.mjs`](../scripts/bench/bench.mjs), `npm run bench`). It boots the app on its own ephemeral Vite port and drives a headed Chrome: move mode (the default) measures mean FPS, frame-time percentiles and per-map render counts under scripted camera motion across component-ablation variants, while load mode measures navigation to a fully loaded, quiet page across cold and warm loads — optionally against the production `dist/` bundle. See [Performance](8.performance.md).

**Brunnel** — _Bridge/tunnel_ — the combined bridge/tunnel attribute in the OMT `transportation` layer, used by the road filters to keep bridges and tunnels out of the surface-aware hierarchy.

**Cadence** — The elevation interval of minor contour lines (`CONTOUR_MINOR_EVERY`, 20 m). The cadence must divide the 100 m index interval evenly so minor lines land symmetrically between index pairs.

**Casing** — The contrasting outline drawn under a road, path or route fill.

**Class** — A value-space term used two ways: OMT feature class (`rock`, `farmland`, `military`, `swimming_pool`…) and OMT POI class (`campsite`, `park`, `beer`, `ferry_terminal`…). The outdoor-POI overlay distinguishes features by its own `kind` attribute; the planet-tile amenities layer filters on the OMT `class` directly.

**Compare app** — The Vue dev app (`dev/`) that renders the outdoor style alongside external providers (OpenGIS Basemap, OpenFreeMap, MapTiler, Thunderforest, Esri, USGS…), either as an overlay swipe via `@maplibre/maplibre-gl-compare` or as two synchronised maps side by side, chosen by the view-mode control and persisted in `localStorage` under `outdoors_dev_viewMode`. The left map also has Hillshading and 3D terrain toggles (both default on, persisted under `outdoors_dev_demHillshade`/`outdoors_dev_demTerrain`, backed by a dedicated `compare-dem` Mapterhorn raster-dem source via `useDemOverlay()` in [`dev/src/composables/useDemOverlay.js`](../dev/src/composables/useDemOverlay.js)). The default comparison provider is the OpenGIS Basemap itself (`DEFAULT_PROVIDER_KEY` in [`dev/src/composables/useProviderSelection.js`](../dev/src/composables/useProviderSelection.js)). It also converts contour labels to feet at runtime (`applyImperialContours()` in [`dev/src/App.vue`](../dev/src/App.vue)), seeds the right map's initial camera from the URL-hash camera via `parseHashCamera()` in [`dev/src/hashCamera.js`](../dev/src/hashCamera.js), and exposes both maps as `window.__outdoorsMaps` for tooling. A static build (`npm run demo:build`) produces the deployable `dist/` output.

**Data floor** — The zoom below which a source carries no data. The OMT `poi` layer's data floor is z14 and path geometry starts at z12 (route members) / z14 (all paths); the overlay sources fill these floors, and the `outdoor-amenities` planet layer additionally renders OMT `poi` classes the basemap skips, from z14.

**Decimation** — Hiding off-cadence contour lines by painting them at opacity/width 0 rather than filtering them out, so one `contour-lines` layer draws both the index and minor tiers and hides the lines between the 20 m cadence.

**Feature toggle** — A boolean constant in the `FEATURES` block at the top of [`scripts/build.mjs`](../scripts/build.mjs) that gates a modification; flip it and rebuild. See [The Style Build](1.build.md).

**Filter** — A style-layer expression that decides which features render. The build writes its own filters for the layers it adds (e.g. `POI_FILTER`); contour tiering and decimation are expressed in paint `case` expressions instead — see _Decimation_.

**Glyphs** — The font glyph PBFs (`{fontstack}/{range}.pbf`) used for symbol labels; self-hosted by the basemap at `www.ogis.org/basemap`.

**Ground raster** — The satellite raster layer (`satellite`, source `esri-satellite`) that the `SATELLITE_GROUND` feature inserts above the natural-earth vectors and below the water — anchored at the first water layer via `waterStackIndex()`, falling back to directly above the `Background` canvas floor. It is painted at a zoom-ramped `raster-opacity` (`GROUND_RASTER_OPACITY`, easing from a higher low-zoom `GROUND_RASTER_OPACITY_LOW_ZOOM` by z14) so the calibrated vectors show through, and the water fills are made translucent (`WATER_TINT_OPACITY`) so they read as a palette tint. See [Natural Earth & the Ground Raster](9.natural-earth.md).

**Handoff zoom** — The zoom at which the basemap's own POI layer takes over from the `outdoor-poi` overlay for a given kind. A kind renders only below its handoff zoom; a `null` handoff means the basemap never draws that kind. See [Outdoor POIs](4.pois.md).

**Hillshade** — The 2D relief-shading layer (`hillshade-layer`) derived from the DEM, fading in across the low zooms.

**Icon role** — A named colour in [`palette.json`](../palette.json)'s `iconRoles` block, referenced by an icon's `primary`/`detail` slots and by `iconOutline`. A role is either a hex value or an `@map.<TOKEN>` reference into the same file's `map` block; the route roles reference `@map.ROUTES.*` so the shields match the route linework.

**Index contour** — The bold contour line at every 100 m (`ele % 100 === 0`), which also carries the elevation label. Contrast with _minor contour_.

**Keyline** — The dark outline baked into a pale icon's raster glyph by `scripts/palette.mjs`. It is configured by `iconOutline` (`role` and `width`) and enabled per icon with `outline: true`; because the sheet is not an SDF atlas, `icon-halo-*` paint cannot provide one at render time.

**Kind** — The outdoor-POI category field (`hut`, `shelter`, `viewpoint`, `campsite`, `picnic_site`, `drinking_water`, `trailhead`, `pass`, `ranger_station`, `castle`, `information`, `parking`, `park`, `toilets`, `playground`, `ferry`, `lighthouse`, `skiing`), distinct from the OMT _class_. `showEle` kinds also carry an `ele` elevation attribute.

**Layer** — A single styled visual element in the style (id, type, source, paint/layout properties). The basemap uses human-readable ids (`Grass`, `Water`, `Footway path`, `Zoo`, `Mountain peak labels`…); layers added by the build use kebab-case ids, often `outdoor-` prefixed.

**Minor contour** — The thin contour lines on the 20 m cadence between index lines, decimated at higher zooms.

**Modification** — An outdoor-specific mutation applied to the basemap style by `applyModifications()` in [`scripts/build.mjs`](../scripts/build.mjs): either a restyle of an existing basemap layer (`setPaint()` by exact id) or the addition of a new source/layer (`insertAfter()`/`insertBefore()` at an anchor). Each modification is gated by a feature toggle.

**Natural earth** — The calibrated landcover/landuse **vector** ground (grass, wood, rock, sand, farmland, heath, built-up landuse…) recoloured by `applyNaturalEarthPalette()` over the canvas floor `applyCorePalette()` tints from the `TERRAIN.BACKGROUND` map token in [`palette.json`](../palette.json) (exposed as `COLOURS.TERRAIN.BACKGROUND`), and retained beneath the Esri World Imagery raster, so the imagery composites over it rather than replacing it. Distinct from the retired `ne2_shaded` relief raster of the same name — not DEM-derived. See [Natural Earth & the Ground Raster](9.natural-earth.md).

**Overlay** — A hosted vector source layered on top of the basemap, consumed by the style by source id and source-layer: the outdoor POIs (`https://tile.ogis.app/pois/{z}/{x}/{y}.pbf`, `outdoor_pois`, z12–16), waymarked hiking and cycling routes (`https://tile.ogis.app/routes/{z}/{x}/{y}.pbf`, `outdoor_routes`, z8–14), low-zoom paths (`https://tile.ogis.app/paths/{z}/{x}/{y}.pbf`, `outdoor_paths`, z9–13) and contours (`https://tile.ogis.app/contours/{z}/{x}/{y}.pbf`, `contours`, z9–14). See [Paths](3.paths.md), [Outdoor POIs](4.pois.md), [Elevation & Terrain](5.dem.md) and [Activities](7.activities.md). The live [source inventory](https://tile.ogis.app/sources) lists each overlay with its build id and TileJSON link; the server is open source at [OpenGIS/tiles](https://github.com/OpenGIS/tiles).

**Overzoom** — Rendering tiles beyond their declared maxzoom (the renderer scales up the last available zoom level).

**Palette** — [`palette.json`](../palette.json) at the repository root, the single source of truth for palette data: `map` holds the map paint tokens exposed to the build as `COLOURS`, `iconRoles` holds named icon colours, `icons` is the icon registry with each icon's role references, and `iconOutline` configures the keyline. `npm run palette:build` renders `icons/` through it into gitignored `build/icons/`; `npm run palette:check` validates `palette.json` and the `icons/` sources and verifies the committed `sprite.lock.json`, with no render or `spreet` required.

**POI** — _Point of Interest_. The project's POI system is config-driven in two tiers: `OUTDOOR_POI` in [`scripts/poi-config.mjs`](../scripts/poi-config.mjs) defines the overlay's kinds, icons and handoff zooms (rendered in one `outdoor-poi` symbol layer), and `PLANET_POI` defines the planet-tile amenities layer (`outdoor-amenities`) read straight from the OMT `poi` source-layer. See [Outdoor POIs](4.pois.md).

**Raster-dem** — The MapLibre source type for elevation tiles; the project's instance is the Mapterhorn `demSource`.

**Render stack** — The ordered [`RENDER_STACK`](../scripts/build.mjs) array that `applyModifications()` walks bottom-to-top: each group is a band of the rendered map (`core` first, `labels-poi` last) carrying documentation metadata and its gated `steps`. Cross-group overrides live in `FINISHING_PASSES`, which runs after the walk so its overrides beat every group above. The stack is the single source of truth for render order. See [Natural Earth & the Ground Raster](9.natural-earth.md).

**Source** — A data provider in the style. `openmaptiles` (vector base) and the basemap's `attribution` pseudo-source (licence text) come from the basemap; the build adds `esri-satellite` (raster ground, while the `SATELLITE_GROUND` feature is enabled), `demSource` (raster-dem), `contour-source`, `outdoor-paths`, `outdoor-routes` and `outdoor-poi` — their order in the generated `sources` object. All attribution strings are build-owned (`ATTRIBUTION`): the basemap string is synchronised onto both the `openmaptiles` source and the `attribution` pseudo-source, and none may be stripped; the Esri credit rides on the `esri-satellite` source and joins the composed attribution line only while that feature is enabled.

**Source-layer** — The named sub-layer inside a vector source that layers reference (e.g. `outdoor_pois`, `outdoor_paths`, `outdoor_routes`, `contours`); snake_case. `outdoor_routes` carries the hiking and cycling route activities: every feature has `activity` and `activities`, and the style's `outdoor-routes-<activity>-…` layer namespace derives from the source id and activity id.

**Sprite** — The icon sprite sheets behind `icon-image` values: the basemap's sheet at `www.ogis.org/basemap/sprite.json` (the `default` sheet) plus the outdoors-owned sheet at `www.ogis.org/outdoors/sprite` (the `outdoors` sheet). The outdoors sheet is built by `npm run sprite:build`, which renders `icons/` through [`palette.json`](../palette.json) into gitignored `build/icons/` and then rasterises those SVGs with `spreet`; only the resulting sprite sheets in `dev/public/` and their `sprite.lock.json` freshness lock are committed. The style's `sprite` property is an array of `{id, url}` pairs; icons are referenced as `<id>:<name>` for a named sheet, or bare `<name>` — a bare name resolves only against the `default` sheet (MapLibre keys non-default sheets as `id:name`, with no fallback). The POI coverage check validates each `icon-image` value against its own sheet — bare names must exist in the `default` sheet, prefixed values in their named sheet — with an orphan check that every outdoors-sheet icon is referenced with the `outdoors:` prefix, failing on a missing icon rather than rendering nothing. The outdoors sheet is raster, not an SDF atlas, so glyph colours — the `iconRoles` values plus any baked keyline — are part of the PNG; `icon-color`/`icon-halo-*` paint cannot recolour or halo it. See [Extending the Icon Set](2.style.md).

**Sprite lock** — The committed `sprite.lock.json`, written by `npm run sprite:build` after `spreet` and the sprite-key check succeed. It records sha256 digests of the sprite sources (`palette.json` and the sorted `icons/*.svg`) and of the four committed sheets in `dev/public/` (`sprite.json`, `sprite.png`, `sprite@2x.json`, `sprite@2x.png`). CI cannot run `spreet`, so `npm run palette:check` verifies the lock instead of rebuilding the sheet: a missing lock or any changed digest fails, naming the missing lock or stale entry. Never hand-edit the lock — regenerate it with `npm run sprite:build`.

**Style** — The MapLibre style: `style.json` at the project root, generated by the build from the basemap and validated against the MapLibre style spec. It is the only artefact the style needs to ship.

**Surface-aware** — The road hierarchy keyed on paved/unpaved `surface`, with unpaved roads drawn narrower and dashed.

**Terrain** — The 3D elevation rendering enabled by the style's `terrain` property (`{ source: "demSource", exaggeration: 1.2 }`).

**Terrain LOD** — The cap on how many zoom levels and how many tiles a raster-dem source loads at high pitch, set via MapLibre's `setSourceTileLodParams(maxZoomLevelsOnScreen, tileCountMaxMinRatio)` (defaults 9.314 / 3.0). The compare app lowers it through `TERRAIN_LOD` in [`dev/src/terrainLod.js`](../dev/src/terrainLod.js); because it is a map-level option, consumers of `style.json` must apply it themselves. See [Performance](8.performance.md).

**Tile** — A square (usually 256 px) map tile at zoom z, column x, row y: `{z}/{x}/{y}.pbf` (vector), `.webp`/`.png` (raster). Some providers use the row-before-column Esri order (`{z}/{y}/{x}`) with no file extension.

**Zoom** — The current zoom of the map (usually 0–18 or 0–20). Referred to using the shorthand `z[zoom_number]`, e.g. z12. Features declare zoom ranges via `minzoom`/`maxzoom` (MapLibre's `maxzoom` is exclusive); _overzoom_ happens when the renderer draws tiles beyond their declared maxzoom.

## Dependencies

**Compare-app providers** — The external styles the dev compare app renders against ([`dev/src/providers.json`](../dev/src/providers.json)).

**Esri World Imagery** — The satellite ground raster provider: ArcGIS `World_Imagery` MapServer tiles from `server.arcgisonline.com` (256 px, maxzoom 20, ArcGIS `{z}/{y}/{x}` ordering), sourced while the `SATELLITE_GROUND` feature is enabled. Attribution-required — the build supplies the compact `© Esri` credit (`ATTRIBUTION.ESRI`) on that source and appends it to the composed attribution line only then. See [Build Script](1.build.md).

**MapLibre** — The open-source map renderer the style targets: MapLibre GL JS / Native, the [style specification](https://maplibre.org/maplibre-style-spec/) the build validates against, and the compare widget. npm dependencies: `maplibre-gl`, `@maplibre/maplibre-gl-style-spec`, `@maplibre/maplibre-gl-compare`.

**Mapterhorn** — The DEM provider ([mapterhorn.com](https://mapterhorn.com/)): Terrarium-encoded WebP raster tiles at `tiles.mapterhorn.com` (512 px, Copernicus GLO-30 base + national/regional LiDAR), with z16 coverage gaps. Powers the style's client-rendered hillshade and 3D terrain. The style declares its `demSource` at 256 px and maxzoom 15, overzooming complete z15 tiles rather than requesting the gap-ridden z16; the 256 px declaration also cuts terrain mesh and texture work. See [Performance](8.performance.md).

**OpenFreeMap (OFM)** — The free planet-wide vector tile provider ([openfreemap.org](https://openfreemap.org/)) behind the basemap: `tiles.openfreemap.org/planet`. Also the source of the compare app's Bright/Dark/Fiord/Liberty/Positron styles.

**OpenGIS Basemap** — The base style this project starts from: the vendored OpenMapTiles OSM style v3.16 pointed at OpenFreeMap planet tiles, published at <https://www.ogis.org/basemap/> (upstream repo: [opengis/basemap](https://github.com/opengis/basemap)). The build fetches its `style.json` and applies the outdoor modifications. See [Build Script](1.build.md).

**OpenMapTiles (OMT)** — The vector-tile schema for the base map ([openmaptiles.org](https://openmaptiles.org/)), translating OSM tags into layers such as `poi`, `transportation`, `mountain_peak` and `landcover`. The basemap is the vendored OMT OSM style v3.16. OMT's zoom-gating shapes the project's data floors: no path geometry below z12, and the `poi` layer emits nothing below z14 — the reason the custom overlays exist.

**OpenStreetMap (OSM)** — The source data for everything: the planet dataset of nodes, ways and relations described by `key=value` tags (`tourism=alpine_hut`, `highway=path`). Attribution: `© OpenStreetMap contributors`.

# Terminology

This glossary defines the vocabulary used across the project, grouped by domain. Each term has one canonical entry.

## Core Concepts

**Basemap** — The OpenGIS Basemap: the OpenMapTiles OSM style pointed at OpenFreeMap planet tiles, published at <https://www.ogis.org/basemap/> (upstream repo: [opengis/basemap](https://github.com/opengis/basemap)). The build fetches its `style.json` from `https://www.ogis.org/basemap/style.json` (tracking upstream `main`), caches it at build time and applies the outdoor modifications on top. See [Build Script](1.build.md).

**Brunnel** — _Bridge/tunnel_ — the combined bridge/tunnel attribute in the OMT `transportation` layer. The project does not filter on it: bridges and tunnels are matched by explicit layer id (`ROAD_BRIDGE_LAYERS`/`ROAD_TUNNEL_LAYERS` and the `* bridge`/`* tunnel` path layers).

**Cadence** — The elevation interval of minor contour lines (`CONTOUR_MINOR_EVERY`, 20 m). The cadence must divide the 100 m index interval evenly so minor lines land symmetrically between index pairs.

**Calibrated** — The natural-earth vectors and the canvas floor beneath them matched to reference imagery so the vector ground and the raster read as one surface. See [Ground Raster](11.ground-raster.md).

**Casing** — The contrasting outline drawn under a road, path or route fill.

**Decimation** — Hiding off-cadence contour lines by painting them at opacity/width 0 rather than filtering them out, so one `contour-lines` layer draws both the index and minor tiers and hides the lines between the 20 m cadence.

**Hillshade** — The 2D relief-shading layer (`hillshade-layer`) derived from the DEM, fading in across the low zooms.

**Index contour** — The bold contour line at every 100 m (`ele % 100 === 0`), which also carries the elevation label. Contrast with _minor contour_.

**Minor contour** — The thin contour lines on the 20 m cadence between index lines, decimated at higher zooms.

**Path family** — The basemap's `Footway path`, `Bridleway path`, `Cycleway path` and `Steps path` layers plus their bridge and tunnel variants, unified by `applyPathStyling()` into one outdoor trail look from z14. The low-zoom paths overlay covers z9–13 beneath it. See [Paths](3.paths.md).

**Reference stop** — A named camera view (centre, zoom and landcover mix) used to tune the ground blend against real imagery; the stop list lives in [Ground Raster](11.ground-raster.md).

**Surface-aware** — The road hierarchy keyed on paved/unpaved `surface`, with unpaved roads drawn narrower and in a light neutral grey.

**Terrain** — The 3D elevation rendering enabled by the style's `terrain` property (`{ source: "demSource", exaggeration: 1.2 }`).

**Terrain LOD** — The cap on how many zoom levels and how many tiles a raster-dem source loads at high pitch, set via MapLibre's `setSourceTileLodParams(maxZoomLevelsOnScreen, tileCountMaxMinRatio)` (defaults 9.314 / 3.0). The compare app lowers it through `TERRAIN_LOD` in [`dev/src/terrainLod.js`](../dev/src/terrainLod.js); because it is a map-level option, consumers of `style.json` must apply it themselves. See [Performance](8.performance.md).

## Style & MapLibre

**Collision / placement** — MapLibre's symbol pass that drops overlapping labels and icons; stack order and symbol-sort-key values decide the winner.

**Expression** — A style-spec JSON array evaluated at render time for filters, paint ramps and `case`/`match`/`interpolate` logic.

**Filter** — A style-layer expression that decides which features render. The build writes its own filters for the layers it adds (e.g. `POI_FILTER`); contour tiering and decimation are expressed in paint `case` expressions instead — see _Decimation_.

**Glyphs** — The font glyph PBFs (`{fontstack}/{range}.pbf`) used for symbol labels; self-hosted by the basemap at `www.ogis.org/basemap`. Not to be confused with sprite icons.

**Icon-image** — A symbol layer's sprite icon reference: `<sheet>:<name>`, or a bare name resolved against the `default` sheet.

**Layer** — A single styled visual element in the style (id, type, source, paint/layout properties). The basemap uses human-readable ids (`Grass`, `Water`, `Footway path`, `Zoo`, `Mountain peak labels`…); layers added by the build use kebab-case ids, often `outdoor-` prefixed.

**Layer type** — The renderer a layer uses: `background`, `fill`, `line`, `symbol`, `raster`, `hillshade` or `fill-extrusion`.

**Overzoom** — Rendering tiles beyond their declared maxzoom; the renderer scales up the last available zoom level. A source's `maxzoom` is the data ceiling, a layer's `maxzoom` is exclusive — see _Zoom_.

**Paint / layout** — Paint properties control appearance (colour, width, opacity); layout properties control placement and geometry (visibility, symbol placement, icon and text layout, line caps and joins).

**Source** — A data provider in the style. `openmaptiles` (vector base) and the basemap's `attribution` pseudo-source (licence text) come from the basemap; the build adds `esri-satellite` (raster ground), `demSource` (raster-dem), `contour-source`, `outdoor-paths`, `outdoor-routes` and `outdoor-poi` when their feature toggles are enabled. All attribution strings are build-owned — see _Attribution_.

**Source-layer** — The named sub-layer inside a vector source that layers reference (e.g. `outdoor_pois`, `outdoor_paths`, `outdoor_routes`, `contours`); snake_case. `outdoor_routes` carries the hiking and cycling route activities: every feature has `activity` and `activities`, and the style's `outdoor-routes-<activity>-…` layer namespace derives from the source id and activity id.

**Sprite** — The icon sprite sheets behind `icon-image` values: the basemap's sheet at `www.ogis.org/basemap/sprite.json` (the `default` sheet) plus the outdoors-owned sheet at `www.ogis.org/outdoors/sprite` (the `outdoors` sheet, built from `icons/` by `npm run sprite:build`). The style's `sprite` property is an array of `{id, url}` pairs; icons are referenced as `<id>:<name>` for a named sheet, or bare `<name>` — a bare name resolves only against the `default` sheet (MapLibre keys non-default sheets as `id:name`, with no fallback). The POI checker validates each `icon-image` value against its own sheet and enforces the prefix rule with an orphan check. See [Sprites & Icons](12.sprites.md).

**Style** — The MapLibre style: `style.json` at the project root, generated by the build from the basemap and validated against the MapLibre style spec. It is the only artefact the style needs to ship.

**`styleimagemissing`** — The MapLibre warning raised when a requested sprite icon is absent; the build and checker aim for zero occurrences.

**Symbol-sort-key** — A layout value ordering symbol placement; lower values place first and win collisions.

**Tile** — A square (usually 256 px) map tile at zoom z, column x, row y: `{z}/{x}/{y}.pbf` (vector), `.webp`/`.png` (raster). Some providers use the row-before-column Esri order (`{z}/{y}/{x}`) with no file extension.

**Token template** — A dynamic `icon-image` template such as `{class}`/`{subclass}`, rewritten by the build into `match` expressions to avoid `styleimagemissing`. The checker scans for any surviving template.

**Web Mercator** — The projection tiles render in; the road width engine converts metres to pixels at `ROAD_WIDTH_REFERENCE_LATITUDE`.

**Zoom** — The current zoom of the map (usually 0–18 or 0–20). Referred to using the shorthand `z[zoom_number]`, e.g. z12. Features declare zoom ranges via `minzoom`/`maxzoom`: a layer's `maxzoom` is exclusive (the layer stops rendering at that zoom), while a source's `maxzoom` is a data ceiling — beyond it the renderer _overzooms_ the last available tiles.

## Build & Render Order

**Anchor** — The layer id relative to which a build modification inserts its layers, preserving the surrounding stack order. Some additions splice at a computed index or push when the anchor is absent. Examples: `contour-lines` is inserted after `River bridge outline`; the POI block sits above `Zoo` (`outdoor-amenities` after `Zoo`, `outdoor-poi` above it); the low-zoom path layers are inserted before `Footway path`; the waymarked-route block after `Disputed border`; `contour-labels` below the basemap's peak label layers.

**Attribution** — The build-owned licence credits in the style. The `ATTRIBUTION` block is the single source of truth: the basemap string is applied to the live `openmaptiles` source and the basemap's `attribution` pseudo-source, the Mapterhorn and MapLibre credits are added, and `metadata.attributionLine` joins the fragments — appending `ATTRIBUTION.ESRI` only when the satellite ground feature is enabled — for use as the map control's `customAttribution`. The compare app's outdoor pane and the screenshot harness pass that line as `customAttribution`.

**Feature toggle** — A boolean constant in the `FEATURES` block at the top of [`scripts/build.mjs`](../scripts/build.mjs) that gates a modification; flip it and rebuild. See [Build Script](1.build.md).

**Finishing pass** — A cross-group override run after the `RENDER_STACK` walk so it beats every band (e.g. the imagery legibility pass). The passes live in `FINISHING_PASSES`.

**Modification** — An outdoor-specific mutation applied to the basemap style by `applyModifications()` in [`scripts/build.mjs`](../scripts/build.mjs): either a restyle of an existing basemap layer (`setPaint()` by exact id) or the addition of a new source/layer (usually `insertAfter()`/`insertBefore()` at an anchor; some splice directly or push). Most modifications are gated by a feature toggle; the sprite wiring and the basemap-POI icon rewrite are unconditional.

**Palette / `COLOURS`** — The `COLOURS.*` config sub-objects (`TERRAIN`, `LANDCOVER`, `LANDUSE`, `WATER`, `PARK`, `ROADS`, `PATHS`, `ROUTES`, `CONTOURS`) read by render bands and layers.

**Render band / group** — One named `RENDER_STACK` entry carrying documentation metadata and gated steps; bands are listed bottom-to-top.

**Render stack** — The ordered `RENDER_STACK` array that `applyModifications()` walks bottom-to-top: each group is a band of the rendered map (`core` first, `labels-poi` last) carrying documentation metadata and its gated `steps`. Cross-group overrides live in `FINISHING_PASSES`, which runs after the walk so its overrides beat every group above. The stack is the single source of truth for render order. See [Render Stack](10.render-stack.md).

**Step** — A `{ when, run }` entry in a render band; `when()` gates it on a feature toggle (or returns true for an always-on step) and `run(style, ctx)` applies it.

## Data & Providers

**Class** — A value-space term used two ways: OMT feature class (`rock`, `farmland`, `military`, `swimming_pool`…) and OMT POI class (`campsite`, `park`, `beer`, `ferry_terminal`…). The outdoor-POI overlay distinguishes features by its own `kind` attribute; the planet-tile amenities layer filters on the OMT `class` directly.

**Contour overlay** — The contour vector source and its two layers — `contour-source` (`https://tile.ogis.app/contours/{z}/{x}/{y}.pbf`, source-layer `contours`, z9–14), `contour-lines` and `contour-labels` — gated by `CONTOURS`. It is independent of the client DEM. See [Elevation & Terrain](5.dem.md).

**Data floor** — The zoom below which a source carries no data. The OMT `poi` layer's data floor is z14 and path geometry starts at z12 (route members) / z14 (all paths); the overlay sources fill these floors, and the `outdoor-amenities` planet layer additionally renders OMT `poi` classes the basemap skips, from z14.

**Esri World Imagery** — The satellite ground raster provider: ArcGIS `World_Imagery` MapServer tiles from `server.arcgisonline.com` (256 px, maxzoom 20, ArcGIS `{z}/{y}/{x}` ordering), sourced while the `SATELLITE_GROUND` feature is enabled. Attribution-required — the build supplies the compact `© Esri` credit (`ATTRIBUTION.ESRI`) on that source and appends it to the composed attribution line only then. See [Build Script](1.build.md).

**Ground raster** — The satellite raster layer (`satellite`, source `esri-satellite`) that the `SATELLITE_GROUND` feature inserts above the natural-earth vectors and below the water — anchored at the first water layer via `waterStackIndex()`, falling back to directly above the `Background` canvas floor. It is painted at a zoom-ramped `raster-opacity` (`GROUND_RASTER_OPACITY`, easing from a higher low-zoom `GROUND_RASTER_OPACITY_LOW_ZOOM` by z14) so the calibrated vectors show through, and the water fills are made translucent (`WATER_TINT_OPACITY`) so they read as a palette tint. See [Ground Raster](11.ground-raster.md).

**Handoff zoom** — The zoom at which the basemap's own POI layer takes over from the `outdoor-poi` overlay for a given kind. A kind renders only below its handoff zoom; a `null` handoff means the basemap never draws that kind, so the overlay renders it at every zoom. See [Outdoor POIs](4.pois.md).

**Kind** — The outdoor-POI category field (`hut`, `shelter`, `viewpoint`, `campsite`, `picnic_site`, `drinking_water`, `trailhead`, `pass`, `ranger_station`, `castle`, `information`, `parking`, `park`, `toilets`, `playground`, `ferry`, `lighthouse`, `skiing`), distinct from the OMT _class_. `showEle` kinds also carry an `ele` elevation attribute.

**Low-zoom paths** — The `outdoor-paths` overlay that fills the OpenMapTiles path gap at z9–13: `https://tile.ogis.app/paths/{z}/{x}/{y}.pbf`, source-layer `outdoor_paths`, with path/footway layers from z9 and track-class layers from z12. It hands off to the basemap's path family at z14. See [Paths](3.paths.md).

**MapLibre** — The open-source map renderer the style targets: MapLibre GL JS / Native, the [style specification](https://maplibre.org/maplibre-style-spec/) the build validates against, and the compare widget. npm dependencies: `maplibre-gl`, `@maplibre/maplibre-gl-style-spec`, `@maplibre/maplibre-gl-compare`.

**Mapterhorn** — The DEM provider ([mapterhorn.com](https://mapterhorn.com/)): Terrarium-encoded WebP raster tiles at `tiles.mapterhorn.com` (512 px, Copernicus GLO-30 base + national/regional LiDAR), with z16 coverage gaps. Powers the style's client-rendered hillshade and 3D terrain. The style declares its `demSource` at 256 px and maxzoom 15, overzooming complete z15 tiles rather than requesting the gap-ridden z16; the 256 px declaration also cuts terrain mesh and texture work. See [Performance](8.performance.md).

**Natural earth** — The calibrated landcover/landuse **vector** ground (grass, wood, rock, sand, farmland, heath, built-up landuse…) recoloured by `applyNaturalEarthPalette()` over the canvas floor `applyCorePalette()` tints from `COLOURS.TERRAIN.BACKGROUND`, and retained beneath the Esri World Imagery raster, so the imagery composites over it rather than replacing it. Distinct from the retired `ne2_shaded` relief raster of the same name — not DEM-derived. See [Natural Earth](9.natural-earth.md).

**OpenFreeMap (OFM)** — The free planet-wide vector tile provider ([openfreemap.org](https://openfreemap.org/)) behind the basemap: `tiles.openfreemap.org/planet`. Also the source of the compare app's Bright/Dark/Fiord/Liberty/Positron styles.

**OpenGIS Basemap** — Alias for _Basemap_: the OpenMapTiles OSM style this project extends, fetched at build time and cached. See _Basemap_.

**OpenGIS tile server** — The hosted `tile.ogis.app` service serving the POI, route, path and contour overlays; source at [OpenGIS/tiles](https://github.com/OpenGIS/tiles). The live [source inventory](https://tile.ogis.app/sources) lists each source with its zoom range, build id and TileJSON link.

**OpenMapTiles (OMT)** — The vector-tile schema for the base map ([openmaptiles.org](https://openmaptiles.org/)), translating OSM tags into layers such as `poi`, `transportation`, `mountain_peak` and `landcover`. The basemap is the OpenGIS Basemap, fetched from upstream at build time. OMT's zoom-gating shapes the project's data floors: no path geometry below z12, and the `poi` layer emits nothing below z14 — the reason the custom overlays exist.

**OpenStreetMap (OSM)** — The source data for everything: the planet dataset of nodes, ways and relations described by `key=value` tags (`tourism=alpine_hut`, `highway=path`). Attribution: `© OpenStreetMap contributors`.

**Overlay** — A hosted vector source layered on top of the basemap, consumed by the style by source id and source-layer: the outdoor POIs (`https://tile.ogis.app/pois/{z}/{x}/{y}.pbf`, `outdoor_pois`, z12–16), waymarked hiking and cycling routes (`https://tile.ogis.app/routes/{z}/{x}/{y}.pbf`, `outdoor_routes`, z8–14), low-zoom paths (`https://tile.ogis.app/paths/{z}/{x}/{y}.pbf`, `outdoor_paths`, z9–13) and contours (`https://tile.ogis.app/contours/{z}/{x}/{y}.pbf`, `contours`, z9–14). See [Paths](3.paths.md), [Outdoor POIs](4.pois.md), [Elevation & Terrain](5.dem.md) and [Activities](7.activities.md). Each overlay is gated by its feature toggle. The live [source inventory](https://tile.ogis.app/sources) lists each overlay with its build id and TileJSON link; the server is open source at [OpenGIS/tiles](https://github.com/OpenGIS/tiles).

**Planet layer** — The `outdoor-amenities` symbol layer that reads selected OMT `poi` classes (`doctors`, `bank`, `bicycle_rental`) directly from the basemap's `openmaptiles` source at z14+.

**POI** — _Point of Interest_. The project's POI system is config-driven in two tiers: `OUTDOOR_POI` in [`scripts/poi-config.mjs`](../scripts/poi-config.mjs) defines the overlay's kinds, icons and handoff zooms (rendered in one `outdoor-poi` symbol layer), and `PLANET_POI` defines the planet-tile amenities layer (`outdoor-amenities`) read straight from the OMT `poi` source-layer. See [Outdoor POIs](4.pois.md).

**POI checker** — `npm run check:pois` (`scripts/check-poi-coverage.mjs`), the coverage check that validates every `icon-image` against its own sprite sheet, catches orphan outdoors-sheet icons, scans for surviving token templates, and verifies the POI kind coverage and sort keys against the shared config and built style. See [Outdoor POIs](4.pois.md).

**Raster-dem** — The MapLibre source type for elevation tiles; the style's DEM source is `demSource` (added when the DEM toggles are enabled), and the compare app adds its own `compare-dem` source for the left pane.

**Satellite ground** — The `SATELLITE_GROUND` feature: Esri World Imagery blended over the natural-earth vectors at a zoom-ramped opacity, inserted above the vectors and below the water. See _Ground raster_ and [Ground Raster](11.ground-raster.md).

**Terrarium encoding** — A DEM tile encoding that stores elevation in RGB channels; Mapterhorn's WebP tiles use it.

**TileJSON** — A JSON metadata document describing a tile source's tiles, zoom range and attribution. The [source inventory](https://tile.ogis.app/sources) publishes a TileJSON link per overlay source.

## Routes & Activities

**Activity** — A waymarked-route mode (`hiking` or `cycling`) registered in the style's `ROUTE_ACTIVITIES` list. A tile feature's `activity` selects its tier family; its `activities` value carries the relation's full set in priority order, which the style uses to decide ownership of shared ways. See [Activities](7.activities.md).

**Badge / shield** — The route marker symbol carrying `ref`/`name`; the shield is a full-bleed sprite stretched with `icon-text-fit` so one flat shape serves every label length. Badges appear on marked networks only.

**Mixed green** — The shared-way colour (`#3f7a4f`) used when both activity toggles are enabled and `activities` names both. It applies at every rank, including unmarked.

**Ownership** — The rule that the highest enabled activity owns and draws a way shared by several activities; the lower activity's layers exclude it, and the owning activity paints it mixed green when both are enabled.

**Route network** — The OSM `network` value (`iwn`/`nwn`/`rwn`/`lwn` for hiking, `icn`/`ncn`/`rcn`/`lcn` for cycling) that selects a route's marked tier; absent means unmarked.

**Route rank / tier** — One of five hierarchy levels — unmarked, local, regional, national, international — that key widths, opacities and badges.

**Route relation / member** — An OSM route relation and its member ways, carried by the overlay tiles as line features.

**Waymarked route** — An OSM route relation rendered as a marked recreation route; hiking and cycling routes become width-tiered line families with badges on the marked networks. See [Activities](7.activities.md).

## Benchmarking

**Benchmark harness** — The performance benchmark for the compare app ([`scripts/bench/bench.mjs`](../scripts/bench/bench.mjs), `npm run bench`). It boots the app on its own ephemeral Vite port and drives a headed Chrome: move mode (the default) measures mean FPS, frame-time percentiles and per-map render counts under scripted camera motion across component-ablation variants, while load mode measures navigation to a fully loaded, quiet page across cold and warm loads — optionally against the production `demo/` bundle. See [Performance](8.performance.md).

**Cold / warm load** — A first load in a fresh browser context (cold) versus a reload in the same context (warm). Load mode measures both.

**Component ablation / variant** — A page-side variant applied to the loaded app — removing or hiding one component (`no-right-terrain`, `no-overlays`…) or changing a map option such as terrain LOD — measured against the `full` baseline.

**DPR** — Device pixel ratio; the benchmark forces it (default 2) as a launch parameter.

**FPS** — Frames per second, derived from `requestAnimationFrame` deltas in move mode.

**Idle run** — A fixed 3 s no-camera-motion sanity run that asserts the on-demand renderer stays quiet (no unexpected renders).

**Load mode** — The mode measuring navigation to a quiet, fully loaded page across cold and warm loads with no camera motion.

**Move mode** — The default benchmark mode: scripted camera motion measures sustained draw performance (FPS, frame times, render counts).

**Quiet** — The load-mode end state: both maps loaded, stationary, and no request in flight for 1000 ms.

**Screenshot harness** — The Playwright harness (`scripts/screenshots/generate.mjs`) that renders the named shots in `shots.json` to the committed JPEGs and serves the local outdoors sprite. See [Build Script](1.build.md).

**Shot** — A named camera scenario (centre, zoom, pitch, bearing) used by the benchmark or screenshot harness.

**Symbol family** — A benchmark grouping of symbol layers (place, road, POI, path, route, contour, park, misc) used by the per-family `no-*-labels` ablation variants.

## Compare App

**Compare app** — The Vue dev app (`dev/`) that renders the outdoor style alongside external providers in a swipe or synchronised side-by-side view, with optional left-map DEM overlays and URL-hash camera handling. A static build (`npm run demo:build`) produces the deployable `demo/` output. See [Compare App](13.compare-app.md).

**DEM toggle** — The left-map **Hillshading** and **3D terrain** checkboxes, persisted in `outdoors_dev_demHillshade`/`outdoors_dev_demTerrain` and backed by the `compare-dem` raster-dem source; the source is removed once both toggles are off.

**Provider** — An external style or map the compare app renders in the left pane, selected from [`dev/src/providers.json`](../dev/src/providers.json). Providers are grouped by category; some require an API key, stored locally in the browser. The default is the OpenGIS Basemap (`DEFAULT_PROVIDER_KEY`).

**Swipe** — The comparison where a draggable divider reveals the provider map over the outdoor style (`@maplibre/maplibre-gl-compare`).

**Sync** — Side-by-side pan/zoom/bearing/pitch synchronisation between the two maps (`createMoveSync()`).

**View mode** — The comparison layout — swipe or synchronised side-by-side — persisted in `outdoors_dev_viewMode`.

# Sprites & Icons

> The two sprite sheets, adding icons and the basemap POI icon rewrite.

Outdoors layers a small sprite sheet of its own over the basemap's, and rewrites the basemap's dynamic POI icon templates so every `icon-image` resolves against a loaded sheet. This page covers the two-sheet wiring, the icon build, route badge shields, the POI icon rewrite and the checker rules.

## The two sheets

The style's `sprite` property is an **array** of `{id, url}` pairs — the MapLibre multi-sprite object form. [`build()`](../scripts/build.mjs) writes it unconditionally — it is not a feature-gated modification — with absolute sheet URLs so both resolve wherever the style is hosted:

```json
"sprite": [
  { "id": "default", "url": "https://www.ogis.org/basemap/sprite" },
  { "id": "outdoors", "url": "https://www.ogis.org/outdoors/sprite" }
]
```

Each sheet loads independently under its id; icons are referenced as `<id>:<name>` for a named sheet, or bare `<name>` — a bare name resolves only against the `default` sheet (MapLibre keys non-default sheets as `id:name`, so an outdoors icon referenced bare would never render). The basemap sheet stays `default` so the basemap's own layer references are untouched.

The outdoors sheet's full inventory lives in `OUTDOOR_SPRITE_ICONS` (with `OUTDOOR_SPRITE_ID` in [`scripts/build.mjs`](../scripts/build.mjs)) — every icon listed there is referenced as `outdoors:<name>`, the `outdoor-poi` overlay's `POI_ICON_MATCH` and the curated `BASEMAP_POI_ICON_REMAP` pairs through `outdoorIcon()`, and the route badges with their literal prefixed names. Because non-default sheets only resolve under their `id:` prefix, an icon missing from the list would never render; the checker's orphan check enforces it. `information` uses the basemap's `office` icon and `ranger_station` the basemap's `wilderness_hut` icon, both bare default-sheet references; the planet amenities layer uses its raw `PLANET_POI` icon values.

## Adding an icon

1. **Drop an OpenMapTiles-style SVG in `icons/`** — 14×14 flat-fill colour-coded silhouettes (8×8 for tiny point icons), matching the basemap's icon family. The route badge shields are the exception — plain full-bleed rounded rectangles that `icon-text-fit` stretches around their text.
2. **Add its name to the expected set** — `EXPECTED_ICONS` in [`scripts/build-sprite.mjs`](../scripts/build-sprite.mjs) and `OUTDOOR_SPRITE_ICONS` in [`scripts/build.mjs`](../scripts/build.mjs), then run `npm run sprite:build`.
3. **Let the build produce the sheet** — [`scripts/build-sprite.mjs`](../scripts/build-sprite.mjs) runs the native `spreet` binary (brew `flother/taps/spreet` — the same sprite tool the basemap repo uses via openmaptiles-tools, installed locally, no docker) over the SVGs in `icons/`, writing the 1x sheet plus the `@2x` retina sheet into `dev/public/` (`sprite.{json,png}` and `sprite@2x.{json,png}`). It then verifies the sprite keys exactly match the expected icon set, failing the build on a mismatch.
4. **Commit the built files** — the files are committed; Vite copies `dev/public` → `demo/` on `demo:build`, so the sheet deploys to `https://www.ogis.org/outdoors/sprite`.
5. **Reference it** — in a layer's `icon-image`: the build's `outdoorIcon()` helper adds the `outdoors:` prefix for POI icons (the route badges use literal prefixed names); every other icon is a bare `<name>` resolving against the basemap's `default` sheet (e.g. `office`, `wilderness_hut`, `camping`).
6. **Run the checker** — `npm run check:pois` validates it; see [Checker rules](#checker-rules).

## Route badge shields

The same sheet carries the waymarked-route badge shields: `route_marked_hiking` in oxblood, `route_marked_cycling` in indigo and `route_marked_mixed` in mixed green. Each is one plain 14×14 full-bleed rounded rectangle rather than an icon with a transparent margin, with cream text; all paint fully opaque, so the pill reads as the exact route token rather than blending with the ground. `icon-text-fit: both` stretches the shield around its label at render time, so one flat shape per activity serves every `ref`/`name` length. There are no per-network shields and no unmarked badge: each activity's marked networks share its one shield, shared ways use the mixed shield when both activities are enabled, and unmarked ways carry no badge at all.

## Basemap POI icons

The basemap's own POI symbol layers use dynamic `icon-image` templates (e.g. `{subclass}`). At urban zooms many resolved names are absent from the basemap sheet, producing runtime `styleimagemissing` warnings and blank icons. [`applyBasemapPoiIcons()`](../scripts/build.mjs) rewrites every such template — and the `Shop` layer's subclass-then-class precedence — into a single `match` over the source key via [`basemapPoiIconExpression()`](../scripts/build.mjs):

- **Curated pairs** (`BASEMAP_POI_ICON_REMAP`, hand-maintained) come first: bespoke outdoors icons (soccer, tennis, ruins…) plus near-miss literals that do exist in the default sheet (`fire_station` → `firestation`, `wine` → `alcohol`, `post` → `post_office`…).
- **Identity pairs** follow: every remaining key of the fetched default sheet maps to itself (`basemapPoiIdentityNames()`), derived at build time from [`fetchSpriteKeys()`](../scripts/build.mjs).
- **Fallback** is `outdoors:dot`, the neutral generic.

Every possible output therefore names an icon a loaded sheet contains. No `["image", …]` probe is used — MapLibre fires `styleimagemissing` for any probe whose name is missing, so matching against the real key list is the only zero-warning approach. The rewrite is unconditional, like the sprite array.

## Checker rules

[`scripts/check-poi-coverage.mjs`](../scripts/check-poi-coverage.mjs) (`npm run check:pois`) enforces the icon rules against the built `style.json` and the shared config, exiting 1 on any failure. The bracketed labels match the script's console output.

1. **`[1]` Sprite validation** — every literal `icon-image` value in `style.json` must exist in its **own sheet** (never the union): bare values in the basemap sprite (`https://www.ogis.org/basemap/sprite.json`, ETag-cached), `outdoors:`-prefixed values in the local outdoors sheet (`dev/public/sprite.json`, built by `npm run sprite:build` — the check fails with a clear error telling you to run it if the sheet is missing). A prefixed value is split at its first `:` and resolved against the named sheet. Dynamic expressions are skipped (token templates should no longer exist — see the scan below).
2. **`[1b]` Orphan icons** — every icon key in `dev/public/sprite.json` must be referenced with the `outdoors:` prefix somewhere in `style.json`, so the sheet can never silently grow an icon that `OUTDOOR_SPRITE_ICONS` forgets.
3. **`[1c]` Token-template scan** — no symbol layer's `icon-image` may still contain a `{class}`/`{subclass}` template. Those resolve at render time by substring substitution and raise `styleimagemissing` for names the sprite lacks, so the build rewrites them into the curated-plus-identity `match` expressions; this check catches a build-side regression rather than a browser-console warning. Recursion reaches match values, fallbacks and `["image", name]` literals.

The non-icon POI coverage checks live in [Outdoor POIs](4.pois.md).

## Local development and deployment

> [!NOTE]
> **Local development** — while `style.json` ships the absolute `https://www.ogis.org/outdoors/sprite` URL, the compare app rewrites the `outdoors` sheet to the Vite-served `/sprite` at runtime when `import.meta.env.DEV` ([`dev/src/App.vue`](../dev/src/App.vue)), and the screenshot harness does the same ([`scripts/screenshots/generate.mjs`](../scripts/screenshots/generate.mjs)), so icons under active development render before a deploy. The basemap `default` sheet stays remote.

> [!NOTE]
> **Deploy dependency** — the outdoors sheet URL is absolute (`https://www.ogis.org/outdoors/sprite`) and only exists once the demo deploys (push to master → GitHub Pages), so the icons render on the deployed site.

# Low-Zoom Paths Overlay

> The low-zoom paths overlay fills the gap where the OpenMapTiles base tileset carries no path geometry below z14: path/footway/track geometry is generated with Planetiler and served from the hosted `tile.ogis.app/paths` service (z9–13) — the tile side is documented in [Tile Server & Hosted Overlays](7.server.md). This page covers the style side: the overlay is wired in by [`scripts/build.mjs`](../scripts/build.mjs) and styled as dashed brown lines that match the promoted base path layer at z14+, so the two sources render as one continuous style. The overlay draws the **path** and **footway** classes only — track ways are excluded and render from z12 via the OMT local-road layers instead (see below), so tracks never appear below z12. The style-side overlay is gated by the `LOW_ZOOM_PATHS` toggle: with the toggle on, the build emits an `outdoor-paths` source and layer; with it off, neither is present.

## Style-side changes — `scripts/build.mjs`

Both the overlay (z9–13) and the promoted base layer (z14+) are styled from the **same shared constants** in [`scripts/build.mjs`](../scripts/build.mjs), so the two sources hand over seamlessly: same colour family, same dash pattern, same round cap/join, and matched widths at the seam. See [The Style Build](1.build.md) for how sections, toggles and constants work.

- Gated by the `LOW_ZOOM_PATHS` toggle; the prominent base-layer path styling lives in the `PATH_STYLING` section.
- The overlay adds a vector source (`outdoor-paths`) and one line layer, gated to low zoom with a low-zoom width ramp, spliced at the POI anchor so the render stack stays **paths → routes → POIs** (paths below route lines, routes below POIs).
- The overlay layer filters the `outdoor_paths` source-layer to the `path` and `footway` classes via the `PATHS_OVERLAY_CLASSES` constant — track ways are excluded.
- Tracks render from z12 through the OMT local-road layers `outdoor-local-fill` / `outdoor-local-casing` instead (surface-aware: pale fill, beige and dashed when unpaved, brown casing). This removes the z12–13 double-draw where the overlay's unfiltered track drawing covered the OMT track fill, and makes low-zoom tracks render identically to the z14+ family. Tracks never render below z12.
- The base layer `road_path_pedestrian` is promoted to render from z14 with the shared width/dash/join constants — no double-draw at the seam, because the overlay's exclusive maxzoom hands off exactly where the base layer begins (z13 → z14, both 2 px wide).

## Verification

Both project builds pass. With the `LOW_ZOOM_PATHS` toggle on, the build emits the `outdoor-paths` source and layer and the compare app renders the dashed brown path/footway overlay; the z13 → z14 handoff is built for no double-draw with widths matched at the seam, and track ways render surface-aware from z12 via the local-road layers.

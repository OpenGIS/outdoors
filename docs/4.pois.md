# Outdoor POIs

> POIs for the outdoors.

[![Outdoor POIs](../screenshots/sunshine-coast.png)](https://www.ogis.org/outdoors/#12/50.77365/-128.39317)

## OSM Tags and Icons

OpenStreetMap describes the world with `key=value` tags: a mountain hut is `tourism=alpine_hut`, drinking water is `amenity=drinking_water`. The style's icons come from the [Maki](https://github.com/mapbox/maki/) sprite, so an entry's icon is simply the name of a sprite glyph.

> [!NOTE]
> [Liberty](https://github.com/maputnik/osm-liberty) builds its sprite from an old snapshot of Maki.

## OpenMapTiles

The [OpenMapTiles](https://github.com/openmaptiles/openmaptiles) schema translates those tags into a `poi` layer of classes — `campsite`, `beer`, `park` and so on. [Liberty](https://github.com/maputnik/osm-liberty) renders the full OMT class universe, but late (from z15) and ranked: each grid cell shows only its most important POIs, in importance order, so dense city cells fill with hospitals, transit and shops while a sparse rural cell shows whatever few POIs it has.

OMT only emits POI features from z14, and below that the `poi` layer carries nothing but railway stations and ferry terminals — so below z14 no POI can come from the base tiles at all.

## POI Promotion

Outdoors replaces Liberty's per-cell rank tiers with the catalogue's class allowlists. A class we care about — campsites, drinking water, picnic sites, trailheads — renders consistently at its tier zoom instead of being a rank casualty of its neighbours, while dense urban classes like bus stops and post boxes are demoted or rank-capped so they never flood a city cell. The result is predictability: the same class renders the same way in every cell.

## Custom Extract

Because OMT can't serve POIs below z14, and can't emit some classes at all (pass, ranger_station, skiing, trailhead), a custom extract is built from the planet OSM dataset with [Planetiler](https://github.com/onthegomap/planetiler) and served from the tile server as a second vector source — `tile.ogis.app/pois`, source-layer `outdoor_pois` (see [Tile Server](7.server.md)).

Features are chosen by the OSM tag selectors in the catalogue, each kind entering at its own zoom — huts and passes as low as z8, most others from z10–13 — which gives trailheads, huts, viewpoints and passes data from far below the z14 floor.

## The Catalogue

[`pois/catalogue.yml`](../pois/catalogue.yml) lists every POI the style cares about. An `ofm` entry is a class allowlist: render OMT class X at this tier, with an optional `rank_max` density cap. A `custom` entry is an OSM tag selector for the hosted extract, with its own `min_zoom`.

Some kinds are declared twice, once per source: the extract covers their below-z14 window while OMT covers z14+, and both render identical icons and labels.

Maki is a naming convention, not a contract — there is no promise a class has a matching glyph. The catalogue maps class/kind to icon explicitly, with a `marker` fallback, and the checker's sprite validation fails the build if an icon name doesn't exist in the sprite, rather than silently rendering nothing.

## Scripts

- `npm run check:pois` runs [`scripts/check-poi-coverage.mjs`](../scripts/check-poi-coverage.mjs), which cross-checks the catalogue against the live OMT `poi` schema and the built style — catching classes OMT can never emit, icons missing from the sprite, and producing a gap report for entries whose zoom sits below the OMT data floor.
- `npm run pois:schema` runs [`scripts/generate-poi-schema.mjs`](../scripts/generate-poi-schema.mjs), which turns the `custom` entries into [`pois/pois-schema.yml`](../pois/pois-schema.yml) — the input to the remote Planetiler build that produces the hosted POI tiles.

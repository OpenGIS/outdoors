# Outdoor POIs

> POIs for the outdoors.

[![Cape Scott](../screenshots/cape-scott.jpg)](https://www.ogis.org/outdoors/#12.93/50.77868/-128.39204)

## Two Tiers

The outdoor POI system is two-tiered, both config-driven:

- **Overlay** — the `outdoor-poi` source. [`applyOutdoorPoi()`](../scripts/build.mjs) adds the `outdoor-poi` vector source (`https://tile.ogis.app/pois/{z}/{x}/{y}.pbf`, source-layer `outdoor_pois`, z12–16) and the `outdoor-poi` symbol layer (minzoom 12). This tier carries the kinds the basemap has no POI layer for (trailhead, pass, ranger_station, lighthouse, skiing…) and the kinds the overlay wants from z12 rather than OMT's z14 data floor. A `symbol-sort-key` derived from each kind's `priority` decides collision order (lower = placed first), mirroring the basemap's rank-as-sort-key convention.
- **Planet layer** — OMT data rendered directly. The `outdoor-amenities` symbol layer draws three OMT `poi` classes (doctors, bank, bicycle_rental) straight from the basemap's `openmaptiles` source at z14+. Its sort key sits at 1000 — above the overlay ladder, so basemap POIs place first — and these amenities win only against the least-important ranks.

The two layers stack just above the basemap's POI stack (`Zoo`): `outdoor-amenities` directly above it, `outdoor-poi` above that (so overlay POIs win collisions), both below the contour labels.

## Config — `scripts/poi-config.mjs`

[`scripts/poi-config.mjs`](../scripts/poi-config.mjs) is the single source of truth for both tiers, imported by the build and the checker so the two can never drift.

[`OUTDOOR_POI`](../scripts/poi-config.mjs) drives the overlay: `sourceId`, `tileUrl`, `sourceLayer`, the zoom bounds and the `kinds` array. Each kind declares:

- **kind** — the category value carried by the tiles
- **icon** — the sprite icon name, stored bare: basemap icons are already bare, and `outdoorIcon()` adds the `outdoors:` prefix at build time for icons in `OUTDOOR_SPRITE_ICONS` (see [Sprites & Icons](12.sprites.md))
- **handoffZoom** — the zoom at which the basemap's own POI layer takes over (`null` = the basemap never draws that kind, so the overlay renders it at every zoom)
- **showEle** — whether the label includes the elevation
- **priority** — the symbol-sort-key weight (lower = placed first = wins collisions). The ladder runs 10 (outdoor identity: hut, pass, trailhead, ranger_station) → 50 (information, parking); [`scripts/poi-config.mjs`](../scripts/poi-config.mjs) is the source of truth for the full mapping.

[`PLANET_POI`](../scripts/poi-config.mjs) drives the planet tier: it reuses the basemap's existing `openmaptiles` source (source-layer `poi`, minzoom 14), and its `kinds` array declares three OMT classes:

| class            | icon             | label       |
| ---------------- | ---------------- | ----------- |
| `doctors`        | `doctors`        | icon only   |
| `bank`           | `bank`           | icon only   |
| `bicycle_rental` | `rental_bicycle` | icon + name |

Each entry declares `class`, `icon`, `showTitle` (whether the label includes the name) and `priority`. The icons live in the basemap's default sprite, with an `outdoors:dot` fallback that never renders since every class has an explicit icon. The planet priority is 1000 — deliberately above the overlay ladder: the basemap's own POI layers sort by feature rank (20–2000, lower = first), so a ladder value would let doctors/bank/bicycle_rental outrank nearly every basemap POI they collide with. 1000 keeps basemap POIs first, these amenities winning only against the least-important ranks (≥1000).

## Handoff

Each overlay kind with a handoff renders only below its handoff zoom (`POI_FILTER`); at/above it the basemap's own POI layer named in the table takes over (Attraction z15, Cultural z15, Ferry z15, Local park z15, Campsite z16, Outdoor z16, Public z16, Accommodation z17, Transport z17, Waste z18), so there are no duplicates and no gaps for those kinds. A kind with a `null` handoff has no basemap counterpart, so the overlay renders it at every zoom. Label text, icons and collision order come from `POI_TEXT_EXPR`, `POI_ICON_MATCH` and `POI_SORT_KEY_MATCH`.

The planet layer has no handoff — it draws classes no basemap POI filter matches (`doctors`, `bank`, `bicycle_rental`), directly from the same `openmaptiles` source the basemap reads.

> [!NOTE]
> **Icons.** The outdoors-owned icons (see `OUTDOOR_SPRITE_ICONS` in [`scripts/build.mjs`](../scripts/build.mjs)) live in the outdoors sheet and are referenced with the `outdoors:` prefix, while basemap icons stay bare. See [Sprites & Icons](12.sprites.md) for the sheet, the prefix rules and the local-development rewrite.

## Checker — `npm run check:pois`

[`scripts/check-poi-coverage.mjs`](../scripts/check-poi-coverage.mjs) runs the following checks against the built `style.json` and the shared config. It exits 1 on any failure, and the bracketed labels match the script's console output. The icon checks — `[1]` sprite validation, `[1b]` orphan icons and `[1c]` token-template scan — are covered in [Sprites & Icons](12.sprites.md#checker-rules); the remaining checks are:

1. **`[2]` Kind coverage** — the `outdoor-poi` layer exists, references the `outdoor-poi` source, and every kind in `OUTDOOR_POI.kinds` appears in its filter.
2. **`[2b]` Sort priority** — every kind in `OUTDOOR_POI.kinds` carries a numeric `priority`, and the `outdoor-poi` layer's `symbol-sort-key` is a match over `kind` covering every kind at its config priority.
3. **`[3]` Planet layer** — the `outdoor-amenities` layer exists with the correct source/source-layer/minzoom, its filter contains every class in `PLANET_POI.kinds`, and its `symbol-sort-key` covers every class at its config priority (its icons are already covered by check `[1]`).

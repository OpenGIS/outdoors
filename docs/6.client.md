# Client-side rendering

> `style.json` is validated against the [MapLibre Style Specification](https://maplibre.org/maplibre-style-spec/) at build.

## Usage

Loading the style in MapLibre GL JS is a matter of pointing a `Map` at it:

```js
import maplibregl from "maplibre-gl";

const map = new maplibregl.Map({
  container: "map", // a named <div> in your page
  style: "style.json",
});
```

## Metric vs Imperial

The style ships **metric-only**: elevation labels use metres (`m`) — contour labels and all peak labels. There is no feet variant in the style.

### Contours

Unit switching can be achieved at runtime, before the map parses the style.

```js
[
  "concat",
  ["number-format", ["round", ["*", ["get", "ele"], 3.28084]], {}],
  "ft",
];
```

### Peak Heights

Unlike the contour label, the four peak label layers (`mountain-peak`, `mountain-peak-secondary`, `mountain-saddle`, `mountain-volcano` use **legacy token strings** such as `"{name:latin} {name:nonlatin}\n{ele} m\n▲"`. Tokens can't be used inside an expression, so an imperial patch must replace the **entire `text-field` string** with a `concat` expression, rebuilding the name fields as `["get", ...]`:

```js
[
  "concat",
  ["get", "name:latin"],
  " ",
  ["get", "name:nonlatin"],
  "\n",
  ["number-format", ["round", ["*", ["get", "ele"], 3.28084]], {}],
  "ft",
];
```

Layers differ only in the trailing glyph: `mountain-peak` ends `"▲"`, `mountain-saddle` ends `"—"`, secondary and volcano end after the unit.

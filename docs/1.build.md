# Build Script

> The `style.json` is generated by `scripts/build.mjs`.

```bash
npm install
npm run build
```

## Basemap Base

The build starts from the [OpenGIS Basemap](https://www.ogis.org/basemap/) — the vendored OpenMapTiles OSM style v3.16 pointed at OpenFreeMap planet tiles (upstream repo: [opengis/basemap](https://github.com/opengis/basemap)). The style is fetched from `https://www.ogis.org/basemap/style.json`, deep-cloned and mutated in place.

The basemap's sources, glyphs and attribution pass through untouched — the published basemap is already fully rewritten (glyphs & sprite point at `www.ogis.org/basemap`, tiles at `tiles.openfreemap.org/planet`, attribution baked into an `attribution` source). The sprite is the one exception: it is re-wrapped into a two-sheet array (see [Sprite Sheet](#sprite-sheet)) — the basemap sheet keeps its `default` id so the basemap's own layer references are untouched, and the outdoors-owned sheet is added alongside.

### Fetch & Cache

[`fetchBasemap()`](../scripts/build.mjs) downloads the basemap style with an HTTP ETag conditional GET:

1. Send `If-None-Match` with the cached ETag (`.cache/basemap-etag.txt`).
2. **304** — the cache is fresh; use `.cache/basemap.json`.
3. **200** — the file changed; download, re-cache and use it.
4. **Network error** — fall back to the cache with a warning (fail only if no cache exists).

The style therefore auto-updates when upstream changes, works offline once cached, and needs no manual version management.

## Structure

The script reflects the bottom→top stacking order. Each feature is one `apply…()` modification function that mutates the in-progress style, with two modes:

- **Restyle** — overrides the paint/layout of an existing basemap layer, matched by exact id ([`setPaint()`](../scripts/build.mjs)). Layers missing from the basemap are skipped silently, so the build stays robust against upstream renames.
- **Add** — inserts new sources/layers (DEM, contours, hosted overlays) via [`insertAfter()`](../scripts/build.mjs)/[`insertBefore()`](../scripts/build.mjs) at a basemap anchor layer, preserving the surrounding stack order.

### Feature Toggles

Every modification is gated by a boolean toggle in the `FEATURES` block at the top of the file; flip a toggle and rebuild. In development the style is automatically rebuilt and the compare app refreshes.

| Toggle                 | Controls                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| `TERRAIN_PALETTE`      | Muted landcover/landuse recolouring (grass/wood greens, warm rock/sand/farmland tones, glacier, background) |
| `WATER_PALETTE`        | Water fills & lines recolouring                                                                             |
| `PARK_DIFFERENTIATION` | Park fill vs national park outline vs park labels                                                           |
| `DEM_HILLSHADE`        | Hillshade layer from the Mapterhorn raster-dem source                                                       |
| `DEM_TERRAIN`          | 3D terrain exaggeration from the Mapterhorn raster-dem source                                               |
| `CONTOURS`             | Hosted contour vector source, line layer and elevation labels                                               |
| `ROAD_SURFACE_AWARE`   | Paved/unpaved road hierarchy on the basemap road layers                                                     |
| `PATH_STYLING`         | Outdoor path family on the basemap path layers                                                              |
| `LOW_ZOOM_PATHS`       | Hosted low-zoom paths overlay filling the z9–13 gap                                                         |
| `OUTDOOR_POI`          | Outdoor-POI overlay + planet-tile amenities layer — both config-driven symbol layers                        |

### Constants & Config

The [`COLOURS`](../scripts/build.mjs) object holds every colour literal in the file, nested by feature `COLOURS.<FEATURE>.<KEY>` rather than hard-coding values.

Each feature's configuration is grouped in its own config block, in the same render order as the toggles, next to the `apply…()` function that consumes them: zoom ranges, opacities, widths, dash arrays etc. The POI expressions — `POI_FILTER`, `POI_ICON_MATCH`, `POI_TEXT_EXPR`, `POI_SORT_KEY_MATCH` and the `PLANET_POI_FILTER`/`PLANET_POI_ICON_MATCH`/`PLANET_POI_TEXT_FIELD`/`PLANET_POI_SORT_KEY_MATCH` equivalents — are derived from `OUTDOOR_POI` and `PLANET_POI` in [`scripts/poi-config.mjs`](../scripts/poi-config.mjs), so the layers can never drift from the schema.

## Sprite Sheet

The style's `sprite` property is an **array** of `{id, url}` pairs — the MapLibre multi-sprite object form (maplibre-gl v5 rejects string arrays and requires absolute URLs, so a relative URL is impossible). [`build()`](../scripts/build.mjs) writes it unconditionally — it is not a feature-gated modification:

```json
"sprite": [
  { "id": "default", "url": "https://www.ogis.org/basemap/sprite" },
  { "id": "outdoors", "url": "https://www.ogis.org/outdoors/sprite" }
]
```

Each sheet loads independently under its id; icons are referenced as `<id>:<name>` for a named sheet, or bare `<name>` — a bare name resolves only against the `default` sheet (MapLibre keys non-default sheets as `id:name`, so an outdoors icon referenced bare would never render). The basemap sheet stays `default` so the basemap's own layer references are untouched. The outdoors sheet's full inventory lives in `OUTDOOR_SPRITE_ICONS` (with `OUTDOOR_SPRITE_ID` in [`scripts/build.mjs`](../scripts/build.mjs)) — all five icons, `trailhead`, `pass`, `dot`, `park` and `skiing` — every one listed there and referenced as `outdoors:<name>` via `outdoorIcon()`. Because non-default sheets only resolve under their `id:` prefix, an icon missing from the list would never render; the checker's orphan check enforces it.

### Building the sheet — `npm run sprite:build`

[`scripts/build-sprite.mjs`](../scripts/build-sprite.mjs) runs the native `spreet` binary (brew `flother/taps/spreet` — the same sprite tool the basemap repo uses via openmaptiles-tools, installed locally, no docker) over the SVGs in `icons/`, writing the 1x sheet plus the `@2x` retina sheet into `dev/public/` (`sprite.{json,png}` and `sprite@2x.{json,png}`). It then verifies the sprite keys exactly match the expected icon set, failing the build on a mismatch. The files are committed; Vite copies `dev/public` → `demo/` on `demo:build`, so the sheet deploys to `https://www.ogis.org/outdoors/sprite`. Because that URL is absolute and only exists after the demo deploys, the icons render once the site is deployed (push to master → GitHub Pages). The screenshot harness serves the same files from `dev/public/` (see [`scripts/screenshots/generate.mjs`](../scripts/screenshots/generate.mjs)).

## The Output

[`build()`](../scripts/build.mjs) fetches the basemap, sets the root `name` to `"Outdoors"` (`STYLE_NAME`), applies the modifications, writes `style.json` and validates it:

1. **Fetch** — [`fetchBasemap()`](../scripts/build.mjs) (ETag-cached, see above).
2. **Identity** — the root `name` property is set to `"Outdoors"`, overriding the basemap's own name.
3. **Sprite** — the root `sprite` property is replaced with the two-sheet array (see [Sprite Sheet](#sprite-sheet)); this always applies.
4. **Modifications** — [`applyModifications()`](../scripts/build.mjs) runs the gated sections in render order.
5. **Write** — `style.json` at the project root.
6. **Validate** — the output is checked against the MapLibre Style Specification ([`validateStyle`](../scripts/validate-style.mjs)); a failed validation exits 1, so a build can never emit an invalid style.

The result is a single self-contained `style.json` at the project root — the only thing the style needs to ship.

> [!NOTE]
> **Why paint expressions instead of filters?** MapLibre GL v5 filter syntax cannot express modulo (`%`), so contour tiering (index vs minor) is done with `case` paint expressions that hide off-cadence lines at opacity/width 0 rather than filtering them out. See [Elevation & Terrain](5.dem.md).

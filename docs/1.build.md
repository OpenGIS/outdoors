# Build Script

```bash
npm install
npm run build   # `scripts/build.mjs` generates `style.json`
```

## The Liberty Base

The build starts from the [OpenFreeMap fork](https://github.com/hyperknot/openfreemap-styles) of [OSM Liberty](https://github.com/maputnik/osm-liberty), tracking the upstream `main` branch. The style is then deep-cloned and mutated in place.

Liberty's label, water, boundary and rail infrastructure is kept; the visual layers — landcover, landuse, roads, buildings, POIs — are replaced with outdoor-first versions.

See [Style Structure](2.style.md) for more details.

## The Build Model

Each feature is one `apply…()` section function that mutates the in-progress style, with four modes:

- **Add** — inserts new layers/sources (hillshade, contours, hosted overlays).
- **Replace** — swaps a Liberty layer group for an outdoor-first version (roads, buildings, POIs).
- **Remove** — deletes layers that don't belong on an outdoor map (urban one-way arrows, rail bridge/tunnel variants).
- **Restyle** — adjusts the paint of a kept Liberty layer (terrain palette, water, path visibility).

Insertion is anchor-based: a section that replaces a Liberty group splices its layers in at the anchor the base layer occupied, so the surrounding stack keeps its relative order.

## Feature Toggles

Every section is gated by a boolean toggle at the top of the file, flip a toggle and rebuild. In development the style is automatically rebuild and the compare app refreshes.

## Render Order

The script walks the features bottom→top of the final layer stack.

## Constants & Config

The [`COLOURS`](../scripts/build.mjs) object holds every colour literal in the file, nested by feature `COLOURS.<FEATURE>.<KEY>` rather than hard-coding values.

Each feature's configuration is grouped in its own config block, in the same render order as the toggles, next to the `apply…()` function that consumes them: zoom ranges, opacities, widths, dash arrays etc.

## The Output

After the numbered section steps in [`build()`](../scripts/build.mjs) run, the style is migrated, finalised, written and validated:

1. **Migrate filters** — Liberty ships expression-style filters; the output targets legacy filter syntax, so [`migrateLibertyFilters()`](../scripts/build.mjs) rewrites every layer's filter at build time.
2. **Substitute domains** — [`finalizeStyle()`](../scripts/build.mjs) replaces the `__TILEJSON_DOMAIN__` placeholders OFM Liberty ships with the real tile domain.
3. **Write** — `style.json` at the project root.
4. **Validate** — the output is checked against the MapLibre Style Specification ([`validateStyle`](../scripts/validate-style.mjs)).

The result is a single self-contained `style.json` at the project root — the only thing the style needs to ship.

> [!NOTE]
> **Why legacy filter syntax?** MapLibre GL v5 changed `["geometry-type"]` to return raw "Multi-" types, silently breaking expression filters — most OSM geometries are multi-part. Legacy `$type` has no "Multi-" support, so `["==", "$type", "Polygon"]` matches both, preserving the old behaviour. See the [MapLibre v5.0.0 release notes](https://github.com/maplibre/maplibre-gl-js/releases/tag/v5.0.0).
